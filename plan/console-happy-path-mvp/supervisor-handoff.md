tests, or the walkthrough. You keep the thread moving, vet decisions before they
reach the maintainer, and protect the record's honesty.

## How to inspect and drive

- **Inspect read-only:**
  `tmux capture-pane -p -t console-happy-path-mvp | tail -N`.
- **Short instruction:** one
  `tmux send-keys -t console-happy-path-mvp -- '<one line>' Enter`.
- **Longer text:** `tmux load-buffer` then `paste-buffer -t`, and VERIFY the paste
  landed (capture the pane) BEFORE pressing Enter. A landed paste renders as
  `[Pasted text #N +M lines]` in the input line; anything else means it did not
  land. **Re-check for an open picker immediately before EVERY paste** — see the
  Corrections log.
- **Idle-plus-queued-input means STUCK, not idle.** Check for a modal or an open
  picker before assuming the session is resting.
- An open `AskUserQuestion` picker SUPPRESSES the overseer daemon's wrap-up
  injection into that pane (the daemon reads it as a structured gate and
  classifies `blocked:human`). When the worker raises one, clear it, answer it, or
  lift it to the maintainer promptly — otherwise the track silently stops being
  supervised. **This track has already lost days to exactly that.**
- Never name a shell variable `TMUX`. Never run `tmux kill-server` on the
  maintainer's socket. Never kill the acting overseer daemon (tmux
  `livespec-overseer:1.1`) — it supervises the whole live fleet.

## Decision-vetting rubric

Escalate ONLY decisions that are BOTH genuinely blocking AND genuinely
human-facing. For this thread that means:

- **Every `plan/operator-surface-redesign/` brainstorm point.** That thread's
  ENTRY GATE is maintainer brainstorm participation — an absolute gate, not a
  step. Those points are not yours to answer, and not the worker's. Your job is to
  make sure they arrive **finished**: evidence assembled, options cut,
  recommendation named, cross-repo constraint stated.
- **What is in and out of the MVP walk.** Narrowing the mission is the
  maintainer's call, never a quiet scope reduction.
- **Dispatcher levers in `.livespec.jsonc`.** These were maintainer-directed once
  already and silently broke the approve valve for a whole session.
- **Spec ratification**, and **billing/account choices** (a supervisor never
  selects a spend option on a worker's modal without explicit authorization).

Everything else: have the worker PREPARE the decision, then surface the FINISHED
question, not the raw problem.

A supervisor MAY discharge an acceptance leg itself when it has INDEPENDENTLY
verified the evidence against the forge (merged PR ancestry, live exercise where
possible — "done" means live-exercised) and records the basis in the close reason.
For THIS thread, "live-exercised" means **at the TUI keyboard against the real
stack**, not via `drive.py` and not against a hermetic fixture.

### No idle, no silent block

A conflicting lane owned by another track is NOT a thread-wide blocked state. If
some action is owned elsewhere: (1) stand down on that action only; (2) enumerate
the remaining non-conflicting work; (3) drive the next concrete safe action
immediately; (4) only if NO legitimate non-conflicting action exists, raise the
blocking question with the recommended answer first. Never convert "someone else
owns X" into idling or a `blocked:` declaration.

Two standing lanes that are legitimately owned elsewhere: the per-state
**valid-verb vocabulary** is owned by `livespec-orchestrator-beads-fabro`

## AskUserQuestion presentation rules

**This repo diverges from the fleet default, deliberately.** `AGENTS.md`
§"Agent interaction" records that this maintainer wants pending decisions
**BATCHED into ONE call (up to 4 questions)** rather than one-per-turn, and
expects everything approved to then be executed end-to-end with each outcome
VERIFIED before it is reported. Repo-local `AGENTS.md` wins here. Do not
"correct" this back to the fleet's one-question-per-turn rule.

Unchanged from the fleet rules: recommended option FIRST, labeled
"(Recommended)"; full repository and work-item names, never abbreviations the
reader must expand; `---` as the final line of the message before the picker (the
picker overlays the last rendered line, and trailing blank lines do not help).

An **"Other" free-text answer may redirect the question's premise rather than pick
an option** — re-verify the redirected target before acting. Observed 2026-07-22:
a question about which items to review was answered by naming five "stale
pending-approval records"; the ledger showed all five already `done`. The right
response was fresh verification and a report back, not literal execution.

## Standing safety clauses

Repeat these in every instruction sent to the supervised session:

- Never pass `--no-verify`; **halt and report on hook failure** rather than
  working around it.
- Never touch another session's worktrees or branches.
- Every tracked-file change goes **worktree → PR → rebase-merge → cleanup**;
  never commit on the primary checkout. Worktrees live under
  `~/.worktrees/livespec-console-beads-fabro/<branch>`, never as peers of the
  clones under `/data/projects`. Use `mise exec -- git commit/push` so lefthook
  actually runs.
- Verify against the FORGE (`origin/master` after a fetch), never a working tree
  that may be stale. "Absent from my working tree" is evidence of nothing.
- Establish outcomes from **artifacts** (merged PR / ledger / journal), never exit
  codes. Build every log timestamp with `date -u`, never by hand.

Repo-specific, each earned:

- **`bd` needs the credential wrapper** — `/usr/local/bin/with-livespec-env.sh --`
  prefixed, or it fails `Access denied`. Batch ledger reads; do not narrate into
  the ledger. Its `auto-backup failed` warning is a known fleet gap, not a defect
  here.
- **Edit `.livespec.jsonc` BY HAND.** `drive --action set-config:<k>:<v>`
  round-trips the file through `json.dumps` and silently strips every comment
  while reporting green (`bd-ib-lmi5`).
- **`gh` is pinned to 2.46.0** — `gh pr checks` has no `--json` there.

For factory dispatches, additionally: prove container ownership by **run-config
argv via an ALL-container scan** — never by image shape, position, or timing; and
treat `exit 137` as **ambiguous** between a kill and normal teardown, never as
kill-proof.

## Corrections

Corrections to THIS supervisor role's own behavior, recorded so successors do not
repeat them. **This log starts effectively empty — this thread had no supervisor
before 2026-07-25.** Append here; do not scatter these.

Seeded from the peer charters in `livespec-overseer`
(`plan/ship-overseer-to-fleet/supervisor-handoff.md` and its predecessor
`plan/cutover-and-shipping/supervisor-handoff.md`), carried forward because they
are role-level rather than track-level:

- **Do not order fallback-less waits.** A hold-for-wrap-up was once ordered that
  the hold itself prevented (the daemon's injection fires on low context + idle
  input; idling burns nothing). The wrap-up arrives as a CONSEQUENCE of real work,
  never as something to wait for.
- **Relay only STABLE conditions.** A foreign track's queue reorder was relayed
  three ways in minutes, twice wrongly. Volatile foreign state does not belong in
  briefs or ledgers.
- **Verify on the forge.** A stale-checkout read — a "retired" thread that was
  live on `origin/master` — reached a durable research note before it was caught.
- **When the worker's verification contradicts the brief, the brief loses.**
- **Billing and account choices are the maintainer's alone.**
- **A verifier must be able to fail.** A sabotage test shipped that asserted only
  a status the healthy case ALSO produced, so it passed either way; caught by
  mutation, not review. Before accepting any test as evidence, ask what injected
  defect would make it red — and prefer to see that demonstrated. This thread's
  own analogue: the six `docs_*_lockstep` gates stayed green through two recorded
  doc rots, because they pin claim STRUCTURE, not claim TRUTH.

Earned on this track:

- **Never paste into a pane with an open picker, and re-check right before every
  paste.** Brief 01 was pasted into a pane checked clear moments earlier; between
  the check and the paste the worker raised its NEXT brainstorm point, and the
  picker swallowed the whole brief. Nothing landed and nothing warned — the pane
  looked normal. Worse, a picker reads pasted text as KEYSTROKES, so an unlucky
  paste can navigate or answer a maintainer-owned question. The window between
  answering one point and the next opening is small and it is exactly when a
  supervisor wants to talk. Capture, confirm no `Enter to select` line, paste,
  confirm `[Pasted text #N]`, then Enter.
- **Serial brainstorm pickers are a supervision outage in disguise.** The worker
  raised its points one per turn, each one re-suppressing the daemon's wrap-up
  injection. Batching is not only this maintainer's stated preference
  (`AGENTS.md`) — it is what keeps the track supervised between decisions.
- **A silent gate is a supervision outage, not a pause.** This thread sat on an
  open `AskUserQuestion` picker from 2026-07-23 to 2026-07-25 with no
  `.overseer-state` marker written. The picker suppressed the daemon's injection
  and nothing else raised an alarm, so a maintainer-owned design question went
  unanswered for days while the track read as merely quiet. A supervisor's first
  sweep on any resume is: is there an open picker, and does the marker file agree
  with what the worker is actually doing?
